# Формулировки для резюме и откликов

## Название проекта

**QA Automation на Python: API, UI, авторизация и SQL**

## Резюме · одна строка

Разработал учебный набор из 149 тест-кейсов с учётом параметризации на Python, pytest и Playwright: API, UI, авторизация и SQLite; настроил запуск в GitHub Actions и сбор диагностических артефактов.

## Резюме · описание проекта

- Организовал 149 собираемых тест-кейсов: 70 API, 41 UI, 31 unit и 7 SQLite; выделил 44 проверки без зависимости от внешних сайтов, включая 6 браузерных.
- Автоматизировал позитивные и негативные сценарии авторизации: Bearer token, неверный пароль, cookies/storage state, logout и повторный доступ к защищённой странице.
- Вынес работу с формой в Page Object, использовал фикстуры pytest, параметризацию и проверки Playwright expect; проверил изоляцию вкладок и контекстов.
- Реализовал подмену HTTP-ответов 200/404/500 и проверки HTTPError/Timeout API-клиента; добавил SQL-проверки связей данных, точечных изменений, duplicate ID и rollback.
- Настроил отдельные CI-запуски локальных, API- и UI-тестов, проверку стиля Ruff, JUnit XML и сохранение Playwright traces/screenshots.

## Короткий отклик

Здравствуйте! Занимаюсь автоматизацией тестирования на Python: pytest, requests и Playwright. В портфолио — 149 тест-кейсов для API, UI, авторизации и SQLite, Page Object, фикстуры, подмена ответов и GitHub Actions. Готов показать код и разобрать решения на техническом интервью.

Ссылка на проект: https://github.com/evgeny-buguev/python-api-tests

Репозиторий приватный: перед отправкой отклика нужно согласовать с работодателем доступ к коду либо подготовить отдельную согласованную публичную копию.

## Короткий ответ «Что именно делали?»

Писал API- и UI-автотесты на Python, проверял JSON, авторизацию и cookies, изолировал тестовые данные и браузерные контексты, подменял ответы сервера и настроил CI с отчётами и traces.

## Конкретный результат

Из упражнений собран единый запускаемый набор: тесты разделены по уровням, внешние сервисы отмечены отдельно, есть выборочный запуск и диагностика падений. Исправлены две проверки disabled, которые раньше не вызывали assertion, и тип INTEGER в SQL-схеме; добавлены две проверки целостности данных.

149 — количество собранных pytest-кейсов с учётом параметризации. Фактические результаты прогонов и ограничения проверки приведены в [REVIEW.md](REVIEW.md).
